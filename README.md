# 热量账本

拍照或按克重记食物，读 Apple Watch 的消耗，算出今天到底是热量缺口还是盈余、具体多少。

**纯前端 PWA，没有任何后端。** 数据存在你自己手机的浏览器里，不上传任何服务器，断网也能记录。

---

## 一、装到手机上

1. Safari 打开 **https://karenwang0013.github.io/calorie-ledger/**
2. 底部「分享」→ **添加到主屏幕**
3. 从桌面点开，全屏运行，跟原生 App 一样

第一次打开建议先做三件事：

- 「我的」→ 填身高体重和目标速度（默认值是占位的，不填算不准）
- 「我的」→ 填 DashScope API Key（拍照识别用）
- 「趋势」→ 记一下今天的体重

> **Key 只存在你手机浏览器里，不在代码里、不在 GitHub 上。**
> 这个仓库是公开的，如果把 Key 写进代码，任何人都能拿去刷你的额度。
> 换设备需要重新粘一次。

---

## 二、每天只做三件事

**1. 吃饭时记一笔（10 秒）**

点右下角 `＋`：

| 方式 | 适合 | 怎么做 |
|---|---|---|
| 📷 拍照 | 外卖、餐厅、看不出份量的菜 | 拍一张，AI 拆成条目并估克重，可以改数字 |
| 🔍 搜索 | 家常菜、包装食品 | 搜「米饭」，选「碗」自动填 150g |
| ✍️ 描述 | 懒得分条 | 打「一碗牛肉面加两个卤蛋」 |

**2. 同步手表**

- **自动**：配一次「快捷指令」，每天 23:00 自动读健康数据写进来（见第三节）
- **手动**：右上角「同步手表」→ 选一张健身 App 活动圆环的截图

**3. 早上称体重**

趋势页 → 记录体重。**这一步最重要**，原因见第五节。

## 三、自动同步手表（免截图）

网页读不到 Apple 健康数据 —— 苹果只把 HealthKit 开放给原生 App，Safari 没有这个权限。
所以走的是「快捷指令 → GitHub → App」这条链路：

1. 每天 23:00，快捷指令「**热量采集**」读当天的「活动能量」
2. 它把结果写进 GitHub 仓库根目录的 `health.json`
3. 打开 App 时自动拉取、合并进当天记录

**全程在后台完成，不会打开浏览器。**

要确认的只有一件事：快捷指令 App → 「自动化」→ 23:00 那条 → 动作里的蓝色「快捷指令」选「**热量采集**」，并且那条自动化的总开关是**打开**的。

失败的晚上，手动兜底：我的 → 手表/消耗数据 → ⌨️ 手动填写。

## 四、两个数字，别搞混

### App 首页的缺口是「估算值」

`消耗 − 摄入`。当天就能看，但有误差：

- Apple Watch 的总消耗本身有 ±10~15% 误差
- 拍照估热量有 ±20~30% 误差
- 克重靠眼估还有误差

### 趋势页给你的是「真实缺口」

```
真实消耗 = 平均摄入 − 体重变化速率 × 7700
```

21 天里平均每天吃 1800 千卡、体重每周掉 0.3kg，真实消耗就是 `1800 + 0.3/7×7700 ≈ 2130`。

这个数把所有估算误差吸收掉了，是唯一不说谎的。代价是要连续记 2~3 周。

**前两周按手表吃，两周后开始信趋势页那个数。**

## 五、算不准的时候

**缺口大得离谱** → 没同步手表，用的是公式估算（偏低）。「我的」看「当前消耗来源」，应该是「基础代谢 + 活动消耗」。

**体重一周没动但缺口很大** → 真实消耗比估的低，或者食物记少了（油、酱汁、饮料最容易漏）。

**减脂速度** → 每周 0.5~0.8% 体重。60kg 的人就是 0.3~0.5kg/周，对应每天 300~550 千卡缺口。长期超过消耗 25% 会掉肌肉。

**平台期** → 体重 2 周不动不算，3~4 周才是。看 7 天平均，别看单日。

## 六、数据与备份

数据在浏览器的 localStorage 里，key 是 `calorie-ledger-v1`。

- 「我的」→ **备份** 导出 JSON（含全部记录）
- 「我的」→ **恢复** 从 JSON 导入
- 「我的」→ **导出 CSV** 给 Excel 看

**换手机、清理 Safari 数据、刷机之前，先备份。**
iOS 的本地存储不是永久的 —— 长期不打开这个 App，系统可能会清掉缓存。

## 七、本地开发

没有构建步骤，改完文件刷新即可：

```bash
cd calorie-ledger
python3 -m http.server 8080
# 打开 http://localhost:8080
```

注意 service worker 需要 `localhost` 或 HTTPS 才会生效。

**改了静态文件后，记得把 `sw.js` 里的 `CACHE = 'ledger-vN'` 版本号加一**，否则用户拿到的还是旧缓存。

## 九、算法

- **消耗**：手表总卡路里 > 基础代谢 + 活动消耗 > 公式估算
- **基础代谢**：Mifflin-St Jeor
- **缺口**：消耗 − 摄入，正数缺口，负数盈余
- **目标缺口**：目标速度 × 7700 / 7，上限为消耗的 22%
- **实测消耗**：体重回归斜率 × 7700，与平均摄入对齐

单日数字有 ±20% 误差，别为一天焦虑。
